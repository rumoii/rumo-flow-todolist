# 日常任务执行与复盘交互方案

状态：A 批已批准并完成本地实现；B 批当前列表选择及批量安排安全已完成，见 [更新与批量操作规格](SPEC-updates-batch.md) 和 [验证记录](EVIDENCE-updates-batch.md)。C 仍待评审，D 需单独授权。A 批规格与验证见 [快捷安排规格](SPEC-task-arrangement.md)。

日期：2026-09-08。源码基线：`9e58a5d`。本文最初记录设计建议；本次仅实施 A 批，并补充快速捕获关闭按钮。没有更改数据库结构、依赖、仓库权限或发布资产。

## 1. 目标与业务边界

主线为 **随手收集 → 安排任务 → 今天执行 → 晚间复盘 → 下一步行动**。优先解决任务执行过程中的发现成本、重复选择和跨页寻找，不新增番茄钟、目标系统、云同步、周复盘或分析报表。

- 今天仍是默认任务工作入口；保留当前侧栏和浅紫主色，不全面重做视觉风格。
- 执行计划表达“什么时候做”，截止日期表达“最晚什么时候完成”。重新安排不修改截止日期、截止时间或提醒。
- 收集箱表示没有归属清单，不等于没有执行计划。“未安排”继续通过总计划筛选，不改变既有收集箱含义。
- 任务只有一个日、周或月计划；细化计划修改同一任务，不复制任务，不自动滚动未完成任务。
- 今日重点属于今天的日计划；普通置顶是清单排序属性，两者不互相替代。不引入重点数量硬上限。
- 草稿保留、正式保存复盘、创建行动、完成任务是四种不同状态。不能为减少点击而暗中合并保存操作。
- 任务事实按完成时间和当前执行计划汇总，不表示历史计划快照。不承诺没有记录的数据能生成历史执行率。

现有业务规则以 [任务计划与心流行动决策](decisions/implemented/2026-09-07-planning-actions.md) 和 [草稿决策](decisions/implemented/2026-09-07-editor-drafts.md) 为依据；本文不修改这两份已实施决策。

## 2. 当前链路与操作成本

以下为源码静态核对结果，不是本轮浏览器实测。步骤按用户操作意图描述，不把展开选择器、输入日期等拆成虚假的精确点击统计。

| 场景 | 当前操作路径 | 衔接成本 / 保留能力 |
| --- | --- | --- |
| 随手记任务 | 全局快捷键或侧栏新建 → 捕获窗口输入 → 保存 → 窗口关闭 | 不切换主页面；默认未安排，可用清单标记归类。保存信息未充分解释后续去哪里安排 |
| 当前页添加 | 今天 / 本周 / 本月输入标题 → Enter | 自动采用当前页面计划精度；总计划、清单等页面添加则默认未安排。两个添加入口的差异需要就地说明 |
| 把未安排任务放到今天 | 总计划选择仅未安排 → 打开任务详情 → 修改执行计划 → 保存 → 返回列表 | 为一个高频计划操作打开完整编辑器 |
| 处理过往任务 | 今天 → 展开过往计划未完成 → 打开详情 → 修改计划 → 保存 | 有提醒，但缺少就地处理动作；今日到期任务与过往任务已有去重逻辑 |
| 标记重点 | 打开日计划任务详情 → 勾选当日重点 → 保存 | 行菜单只有置顶和优先级；容易把排序置顶理解为今日重点 |
| 周计划细化 | 本周待细化 → 拖到某日 | 已有直接拖放；日卡片与普通任务行入口不同，不能只改普通行而遗漏周视图 |
| 批量安排 | 展开批量管理 → 在另列的标题列表勾选 → 选择操作及参数 → 应用 | 与正文列表重复呈现任务；今天的提醒区不在传入批量栏的 `filteredTasks` 内 |
| 晚间复盘 | 心流 → 每日复盘 → 查看任务事实 / 填三问或六问 → 保存 | 三问六问已共享草稿；心流初始页签是输入记录，不能把“没有直达复盘入口”当成复盘功能缺失 |
| 从复盘创建行动 | 保存正文 → 创建关联任务 → 确认计划等信息 → 创建 → 点击关联标题 | 支持多个行动和双向来源链接，但结果列表只显示标题、完成 / 删除状态，缺少计划去向 |
| 查看行动后返回 | 关联标题 → 总计划中的任务详情 → 来源链接或重新进心流 | `openTask` 切到总计划，当前窄导航接口没有来源返回上下文；不是“无法返回”，而是缺少直接回到原位置的动作 |

## 3. 优先问题与建议

优先级表示建议开发先后，不表示已确认的故障等级。除明确注明外，以下是交互改进候选，尚未经可用性测试证明影响大小。

| 优先级 | 源码事实 / 设计判断 | 用户影响 | 建议 | 边界 |
| --- | --- | --- | --- | --- |
| 高 | E1–E3：计划展示与计划编辑入口分离 | 常用重新安排需要进入详情 | 可点击的计划按钮和统一安排浮层 | 展示 + 状态协调；草稿写入边界需技术确认 |
| 高 | E2–E3：重点在详情，菜单是普通置顶 | 可能误解两个概念 | 今天行内星标；其他页面明确写“安排到今天并设为重点” | 复用计划 / 重点字段，不改普通置顶语义 |
| 高 | E2：到期与过往提示排在执行列表之前 | 提醒可能抢占今日执行的视觉优先级 | 今日重点与今天任务在前，待处理提醒在后并保留计数 | 展示顺序候选，不改变到期判定 |
| 高 | E4：批量管理重复列出标题 | 选择脱离正在看的任务上下文 | 在原任务行 / 卡片开启选择模式 | 状态协调；选择范围变化需评审 |
| 中 | E1：当前页添加与全局捕获计划默认值不同 | 不知道任务为何进入或未进入今天 | 添加区域显示计划去向提示，保存结果说明归属 | 文案与反馈，不改变默认值 |
| 中 | E5：进入心流默认显示输入记录 | 晚间复盘多一个定位步骤 | 今天页提供“复盘今天”，直达当天复盘 | 窄导航扩展，保留侧栏心流既有行为 |
| 中 | E6：行动结果没有计划摘要 | 创建后不清楚安排到了哪里 | 创建成功摘要 + 原位查看行动 | 创建响应复用；持久列表摘要可能需契约扩展 |
| 中 | E6：跨域导航没有来源返回状态 | 看完任务后需要再次寻找复盘位置 | 有边界的“返回复盘 / 返回输入记录”上下文 | 渲染进程导航状态，不新增数据库记录 |

不在本轮顺带修复其他视觉或代码问题。遇到可疑异步行为时单独记录、复现后再决定，不从源码片段直接宣称运行故障。

## 4. 低保真布局与操作说明

方括号表示可操作控件；数量、任务名和日期均为设计样例，不是用户数据或应用截图。各图表达信息层级，不规定最终像素布局。

### 4.1 今天页：执行优先，提醒不消失

```text
今天                                      [选择任务] [复盘今天]
安排今天要做的事。截止日期不会随计划一起修改。
[添加一个任务……                               Enter 保存]
新任务：计划今天 · 未设为重点

今日重点 · 2
○ 整理方案       [计划：今天 ▾]  截止：周五  [★ 取消重点] [···]
○ 回复问题       [计划：今天 ▾]              [★ 取消重点] [···]

今天的其他任务 · 3
○ 阅读材料       [计划：今天 ▾]              [☆ 设为重点] [···]

待处理提醒
[▸ 今日到期，但未安排在今天 · 2]
[▸ 过往计划未完成 · 4]
  展开后的任务行：原计划 / 截止日期 [安排到今天] [其他安排 ▾]
```

- 今日重点区始终有标题；为空时提示“把今天最重要的任务标为重点”，不显示“暂无置顶任务”。没有今天任务时保留快速添加和待处理提醒，而不是用空状态覆盖提醒。
- 普通行点击标题打开详情；点击计划只打开安排浮层；点击完成按钮只完成任务。星标是独立按钮，不让整行承担多个隐式动作。
- 今天以外的任务不得只显示“设为今日重点”：采用“安排到今天并设为重点”，明确它同时改变计划。取消重点仅清空重点，不移除今天计划。
- 到期 / 过往分区保持既有任务身份和去重顺序；改变计划成功后按服务端结果重新归类。不额外新增“所有已逾期”的重复面板，截止逾期仍由既有逾期视图承担。
- 搜索、标签过滤应一致作用于今天正文和提醒区；计数标明当前筛选结果。提醒优先级和统一筛选是待批准的展示行为变更，不在实现中悄悄扩大或缩小数据范围。
- 保存或完成使任务离开当前列表时，显示结果说明，并将键盘焦点放到同区下一项、上一项或分区标题；不自动跳转到别的页面。

### 4.2 统一安排入口：快捷目标与精确调整并存

```text
[计划：本周 ▾]
┌ 安排任务 ───────────────────────────┐
│ 当前：本周；截止：9 月 11 日          │
│ [今天] [明天] [本周] [本月]          │
│ [改为未安排]                         │
│                                     │
│ 指定计划：[日 / 周 / 月] [日期选择]    │
│ 周计划预览：9 月 7 日—9 月 13 日      │
│ 不修改截止日期                       │
│                         [取消] [应用]│
└─────────────────────────────────────┘
```

- 快捷目标点击即提交；下方指定计划先编辑、再应用。取消或 Escape 不写入。选择当前相同计划不发无意义请求。
- 今天 / 明天以本地日历日期计算；周从周一开始，月为自然月。跨午夜提交时重新计算相对日期；明确日期选择不随午夜变化。周 / 月显示范围预览，避免规范化日期被误解为仅安排某一天。
- “改为未安排”只清除执行计划和失效的重点，不改变清单、标签、截止日期或任务状态。当前计划不变时保留重点；跨日或改成周 / 月 / 未安排时清除原重点。
- 提交中禁用同一任务的安排入口，成功后再展示新计划；失败保留旧值、目标和重试入口。不要先让任务消失，再无提示地回滚。
- 同一任务存在未正式保存的详情草稿时，不直接改正式计划，也不替用户提交其他草稿字段；提示“该任务有未保存修改，请先在详情中保存或放弃”，提供打开详情入口。`drafts.flush()` 仅表示草稿落盘，不能当作解决冲突。
- 普通行、提醒行、月分区和周卡片共用安排行为；周视图原有拖放保持可用，并纳入相同的错误反馈和草稿冲突验收。详情编辑继续在用户点击“保存更改”时提交，不与快捷操作混为一条自动保存路径。
- 不新增计划撤销机制：既有完成 / 删除撤销保持原样。避免无版本保护的“撤销安排”覆盖后来发生的有效修改。

### 4.3 批量选择：在当前列表选，不再复制任务列表

```text
今天                         [退出选择]
┌ 已选 2 项 [选择当前范围] [清空] ──────┐
│ [完成] [安排 ▾] [移动清单 ▾] [更多 ▾] │
└──────────────────────────────────────┘
今日重点
[✓] 整理方案          计划：今天   截止：周五
[ ] 回复问题          计划：今天
其他任务
[✓] 阅读材料          计划：今天
[▸ 今日到期，但未安排在今天 · 2]
```

- 显式进入选择模式；选择框不复用完成按钮。选择模式下保留标题打开详情，但暂停拖放和行内修改操作，避免误操作；不会在批量栏另列标题副本。
- 当前范围为当前页面、当前搜索 / 标签 / 状态筛选下已展开分区中的可选任务，包含滚动区尚未进入视口的行，但不含折叠分区、其他页面、详情子任务或回收站。按任务 ID 去重。
- 今天提醒区展开后可参与选择；周视图按卡片、月视图按分区复用同一选中集合。不使用多套选择状态。
- 更换页面、搜索或筛选条件时清空选择并提示；折叠分区移除其中选择；只改变排序 / 分组且候选任务集合不变时保留选择。刷新后移除已删除或已不可见任务，并更新计数。
- 最多选择 500 个，和既有后端一致。范围超过 500 时禁用“选择当前范围”，提示缩小筛选；不静默截取前 500 项，也不拆成多个伪原子批次。
- 操作能力与现有批量命令一致：完成、安排、移动清单、添加标签、调整截止日期、移入回收站；不在同批新增批量重点、恢复或永久删除。
- 参数尚未完整时不允许应用；删除单独确认任务数。请求中锁定选择和提交；服务端失败时保留选择与参数，无部分成功提示。写入已成功但刷新失败时说明“操作已保存，列表刷新失败”，只重试刷新，不再次提交业务操作。
- 有未保存任务草稿的批量计划操作，建议整批拒绝并指出需处理的任务，不能跳过其中几项。后端原子性和跨窗口校验属于第二批实施前必须确认的技术条件。

### 4.4 复盘与行动：先看事实，再决定下一步

```text
每日复盘 · 今天                       [输入记录] [选择日期]
[▸ 当日已完成 4 项 · 当前日计划未完成 2 项]
  按完成时间和当前计划汇总，不是历史计划快照。

[展开完整复盘（6 问） ▾]          草稿已保留 / 保存失败
1 今天做好了什么？                         [正文]
2 今天有什么可以改进？下次可以怎么做？     [正文]
3 明天有什么期待？准备从哪一步开始？       [正文]
                                         [保存今日复盘]

下一步行动
正文未保存：先保存复盘，再创建关联任务。     [保存复盘]
正文已保存：                              [创建关联任务]
已创建：整理提纲 · 计划明天 · 收集箱        [查看任务]
○ 整理提纲                ✓ 已完成的行动
```

- 今天页“复盘今天”直达本地当天复盘页签；侧栏心流仍保持已有页签行为。输入记录、额度、提醒、月历和三问 / 六问能力保留，不迁入设置、不新增复盘导航层级。
- 未保存或正文有更改时，行动区显示明确原因和调用既有保存逻辑的按钮；这只保存复盘，不自动创建行动。草稿已保留不能解除正文保存条件。
- 行动表单保留标题、计划、清单、截止日期；复盘默认行动计划仍是操作当天的明天，视频默认未安排。历史复盘场景标明“默认安排到明天（实际日期）”，不偷偷改成历史来源日期的下一天。
- 创建成功停留在来源页面，显示实际计划与清单去向，用户主动点击才跳到任务。确认成功与随后刷新失败分开反馈；不因刷新失败重新生成创建请求。
- 结果不确定时保留原请求编号和负载重试；已明确成功后允许再次创建新的行动。不能通过重复点击生成重复任务。
- 从来源打开行动详情时记录来源日期、页签、必要的视频定位、滚动位置和触发按钮；显示“返回复盘”或“返回输入记录”。返回前等待草稿落盘；失败则留在当前页并提供重试。
- 返回上下文只在当前导航链有效，不跨重启保存；主动切换侧栏页面后清除。被定位内容已删除时返回所属日期 / 页签并显示说明，不跳到其他任务。历史搜索原有范围不变，来源已删除仍显示现有最小来源信息。

### 4.5 共同的视觉与键盘规则

- 保留紫色主操作、浅色次级按钮、文字型导航的层级；“安排”“选择任务”“创建关联任务”应能被直接识别为操作，不能仅靠颜色或 hover 暗示。
- 桌面密度仍服从现有舒适 / 紧凑设置。小窗口优先换行并将低频项收入“更多”，不遮住任务名称、选中数量或确认操作；不新增侧栏业务入口。
- Tab 能到达计划、重点、选择框及确认按钮；Enter / Space 激活按钮，Escape 关闭当前浮层，焦点返回触发位置。键盘用户必须能完成周计划细化，不依赖拖拽。
- 加载状态不是空状态：显示加载与重试；按钮等待明确结果，错误不能仅用短暂 toast 表达。保留输入和所在位置，用户可知道失败在哪一步。

## 5. 实现影响与职责边界

本节保留各批的职责设计。A 批采用 `tasks.arrange` 窄接口及窗口屏障，见 [安排决策](decisions/implemented/2026-09-08-task-arrangement.md)；其余接口调整仍待评审。没有新增持久化实体或备份格式。

| 子系统 | 优先复用 | 可能需要的调整 / 必须验证的边界 |
| --- | --- | --- |
| 添加与捕获 | 现有创建、捕获草稿提交、Quick Add 解析 | 按实际保存结果显示“已保存到某清单 · 未安排”；不得无视 `~清单` 一律称收集箱。保持当前自动关闭时机，不新增捕获后自动跳页 |
| 单任务安排与重点 | `planFor`、任务更新、详情草稿、跨窗口通知 | 安排 UI 共享小组件；写入逻辑使用窄任务操作接口。普通行 / 周卡片 / 提醒行共同消费，不让按钮注入整个工作区来复制规则 |
| 草稿冲突 | 草稿协调器、修订与数据代际检查 | 新增快捷写入会和正式编辑并存；仅在渲染进程读取一次草稿无法保证跨窗口安全。实施前定位主进程校验边界，确保快捷计划命令不能覆盖未提交草稿；不能把限制无差别套到草稿正式提交自身 |
| 批量选择 | `tasks.batch` 及现有事务、范围上限 | 选择集合由当前任务页负责；工具栏只接收选择、参数和回调。移除旧的重复标题选择列表，不保留两套交互。计划草稿冲突的整批处理需在主进程同事务确认 |
| 行动结果 | `createAction` 已返回完整 Task，已有幂等请求和来源检查 | 本轮候选优先用创建返回值显示成功摘要；持续的关联列表保持现有最小摘要。若以后要求每条历史行动都展示最新计划，应另评审 `ActionLinkView.task` 的最小字段扩展，不能在每个视频下读取全量任务 |
| 导航返回 | `WorkspaceNavigation` 与现有 `flowTarget` | 在渲染进程增加一次来源返回上下文及返回操作，覆盖跨页序列、滚动与焦点；不是通用路由系统，也不增加数据库表 |
| 复盘保存 | 既有 `saveReview` 与草稿提交 | 行动区保存按钮复用同一保存入口和处理中状态；不得另造第二套保存函数。区分提交失败和保存后的概览刷新失败 |

模块化只围绕三处确有共享需求的职责：安排 UI / 操作、列表选择状态、导航返回状态。保留已有任务、组织、草稿和行动服务分工，不引入通用事件总线或整体替换 `useWorkspace`。

## 8. 评审结论入口

已确定：任务执行优先；先完整设计后分批开发；不新增业务大模块；不自动顺延；不为兼容错误实现增加适配层。

A 批的今天页层级、直接安排及草稿规则已确认并实施。其余两组仍待确认：

1. **今天页层级**：接受执行列表在前、提醒在后，提醒和正文遵循同一筛选；不会改变截止日期判定。
2. **直接安排与草稿**：接受快捷目标点击即生效、指定计划显式应用；有未保存详情草稿时先处理草稿，而不是自动合并或提交。
3. **批量范围**：接受只操作当前过滤后且已展开的范围，更换页面 / 筛选清空选择；已折叠分区不参加全选。
4. **复盘衔接**：接受今天直达复盘和单次来源返回上下文；保存与创建继续分开，历史复盘不默认生成历史待办。

A 批完成不同时授权 B / C / D；涉及其他有效业务行为的后续变更，仍需确认其影响。
