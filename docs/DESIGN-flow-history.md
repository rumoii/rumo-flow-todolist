# 心流历史与任务标识

## 交互约定

- 任务重要程度表示长期高、中、低，未设置不显示标签；今日重点仍表示某天优先执行。排序、分组及筛选字段不变。
- 计划选择器使用按日、按周、按月安排；快捷安排立即生效，自定义安排点击保存计划生效。
- 历史采用按月份分组的时间轴手记，日期倒序。摘要摘录正式记录，不生成标题或总结；展开只读正文，编辑复用每日编辑器。
- 可同时展开多天。编辑返回保留筛选、已加载日期、展开状态及页面滚动位置。日历按需打开。
- 补录归属所选日期，不打开外部来源、不触发继续观看确认。首次记录采用当前额度，已有日期保留额度。

## 数据边界

- `flow.history` 由心流仓储持有，查询实现独立。参数为日期范围、关键词、待补思考及已复盘条件、可选的排他日期游标；每页 30 个日期，以额外一条判断后续页。
- 所有筛选条件共同生效，关键词按字面匹配正式视频标题、作者、思考及正式复盘正文。草稿和无视频、无正式复盘的日期不进入列表。
- `flow.getDay` 读取不存在日期时返回空日模型，不插入记录；历史查询同样只读。实际保存沿用现有视频和复盘表，无数据库结构或备份格式变化。
- 新增历史查询与更新错误详情接口的生产者、preload、前端和测试一起调整，不提供旧接口适配层。
- 查询与每日编辑分别管理异步状态，过期查询不能覆盖新筛选结果；切日失败保留原日期与输入。

## 更新错误

主进程负责错误分类与技术信息脱敏，界面只展示简短说明。技术详情默认折叠，展开后在 180px 内滚动，可手动复制。缺少更新元数据不等于没有新版本。此改动不修改或发布 GitHub Release。

## 验证入口

- `tests/flow-history.test.ts`：隔离 SQLite、只读空日、历史补录、额度、日期游标与筛选。
- `tests/FlowView.test.ts`、`tests/useFlowHistory.test.ts`：草稿保留失败、加载失败、旧请求失效和订阅释放。
- `tests/e2e/flow-history.spec.ts`：45 天浏览器样例、多日展开、编辑返回、日期补录、长错误框和小窗口下拉框；样例不证明真实数据库或更新服务。
- `tests/electron/flow-history.spec.ts`：隔离用户目录中的真实 IPC、草稿提交、分页查询与重启后重读。不会访问日常用户数据。
