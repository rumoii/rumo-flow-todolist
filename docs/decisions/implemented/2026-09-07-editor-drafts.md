# Decision: 独立草稿与模块职责

Status: implemented（纳入 v0.7.0-rc.1；验证层级见 [验证记录](../../EVIDENCE-stabilization.md)，不代表安装升级已验收）

## Problem

任务界面集中管理多个业务，心流组件销毁会丢失输入；全局新建依赖当前页面的输入框。保存业务数据与保留未完成输入需要不同语义。

## Decision

后续任务自动保存、离开检查和新增输入草稿见[编辑体验决策](2026-09-09-editor-experience.md)，其发布候选与验证边界单独记录。

- 保留 Vue、Electron 与单一 SQLite；按任务、组织信息、心流、设置和草稿划分状态及数据操作。
- 全局新建统一进入快捷捕获，主进程在业务写入成功后通知相关窗口。窗口同步不得覆盖正在编辑的表单。
- 迁移 8 使用独立草稿表。类型与对象编号定位草稿，修订号防止乱序写入；清空采用保留修订号的空记录，避免迟到请求让草稿复活。
- 正式保存走业务校验，与草稿清理共享事务；草稿本身不改变任务和复盘完成状态。
- 备份 v4 包含草稿。导入原子替换并更换数据代际；旧窗口的请求不能写入恢复后的数据。
- 所有窗口在备份、恢复和正常退出前确认草稿写入，超时或失败中止操作。退出时只能由用户明确选择放弃最后未落盘的输入。
- 应用通过单实例锁保证同一用户目录只有一个主进程写入；测试通过独立用户目录隔离。

## Alternatives considered

- 只用 KeepAlive：只能解决本次进程内切页，无法跨重启恢复。
- 自动写正式表：会改变手动保存与复盘完成含义。
- localStorage 或单独 JSON 草稿：无法和 SQLite 正式提交、恢复操作共享事务。
- 新增状态框架或服务进程：现有 composable 与主进程能够承载当前边界，没有必要增加运行依赖。

## Consequences

新增草稿协议、窗口写入确认和备份 v4；旧版应用不能读取新备份。只承诺恢复已确认落盘的输入，不承诺强制终止前未确认的输入。正式记录变化需要用户确认，不能静默覆盖。

## Verification

测试覆盖草稿独立保存、修订号与代际冲突、事务回滚、删除关联清理、旧 schema 迁移及旧备份读取。真实 Electron 测试覆盖多窗口、重启、强制退出、备份恢复及手动提交；浏览器模拟接口测试单独报告。

## Rollback

升级前用旧版应用导出旧格式备份。需要降级时正常退出新版，使用旧版与旧格式备份恢复；不要让两个版本同时写同一用户目录。新增草稿不能通过旧版管理，v4 快照应保留供新版恢复。个人数据库、安装与发布操作不由本次实现自动执行。
