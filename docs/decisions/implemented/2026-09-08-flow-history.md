# Decision: 心流历史只读查询与每日编辑分离

Status: implemented

验证覆盖源码、浏览器样例和隔离 Electron；未更新日常安装或发布。

## Problem

日历适合跳转，不适合连续回顾。每日编辑器持有草稿和表单，直接在历史列表重复装载编辑器会增加多日期草稿、保存和滚动状态的复杂度。原读取日期操作会创建空日，不适合历史浏览。

## Decision

- 历史列表独立负责日期筛选、关键词、日期游标分页和只读展开；正文编辑继续使用现有每日编辑器及草稿协调器。
- 每日读取和历史查询均不创建业务记录，IPC 查询不广播数据变更；实际保存才写入原有表。
- 摘要只取正式记录。新建和修改允许历史日期，补录不触发当天的外部观看行为。
- 每日编辑返回保留列表状态；异步查询按请求序号丢弃旧结果，日期切换加载失败不改变原记录归属。
- 具体界面和接口见 [设计说明](../../DESIGN-flow-history.md)。

## Alternatives considered

- 每天直接挂载编辑器：重复草稿所有权和保存控制，不符合以阅读为主的历史体验。
- 只增强日历或复用全局关键词搜索：不能满足连续回顾和不记得关键词时的浏览。
- 新建历史副本表：现有正式视频与复盘已能提供内容，没有额外存储和同步的必要。

## Consequences

新增历史查询契约，与 preload、IPC 和前端同步调整；不改表结构、备份格式或任务重要程度的底层值。首度补录采用当前额度，已经存在的历史日期保留原额度。

## Verification

隔离 SQLite 测试覆盖空日期只读、补录、筛选及超过一页的跨月记录；组件测试覆盖切换失败和过期响应；浏览器样例覆盖多日展开和编辑返回；真实 Electron IPC 测试覆盖草稿提交、分页和重启后重读。更新下载及日常安装不属于这些验证。

## Rollback

代码按同一契约整体回退；无数据库迁移需要撤销。已补录内容仍是原有视频和复盘记录，不删除用户数据。
