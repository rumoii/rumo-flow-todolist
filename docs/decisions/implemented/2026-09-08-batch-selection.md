# 决策：当前范围批量选择与安排同步

状态：已实施；范围限定于源码、临时 SQLite 与桌面验证。

## 问题

旧批量管理重复显示标题列表，选择与页面内容分离；安排命令通过完整任务更新重置重点和提醒标记，没有跨窗口草稿保护。

## 决策

任务页持有唯一选择集合，原任务行和周卡片通过窄上下文消费。候选是筛选后已展开的任务，包含滚动区域内未入视口的行，不包含折叠分区或其他页面。切换范围清空，排序保留，数量限制 500。

批量请求统一携带任务版本和数据库代次，事务检查所有目标后执行。回收站同步调整请求，恢复和永久删除的原有规则不变。批量安排先保留所有窗口草稿；任一目标存在详情草稿时整批拒绝，只修改计划、重点和单调修改时间。

生命周期恢复协议统一返回任务同步数组，单项安排也使用数组。各编辑器只同步无草稿、无未落盘修改且代次一致的缓存；不覆盖有效输入。

## 被否决的方案

- 保留旧标题选择区：继续制造两套选择状态。
- 忽略存在草稿的部分任务：批量结果不再原子。
- 重用完整任务更新做计划修改：会改变截止提醒等无关字段。

## 后果

主进程、preload 和 renderer 必须整体交付。服务端失败保留选择，写入成功后列表刷新失败仅重试读取。批量业务动作、回收站和数据格式没有新增。

## 验证

规格见 `docs/SPEC-updates-batch.md`，最终结果见 `docs/EVIDENCE-updates-batch.md`；测试覆盖范围切换、事务回滚、草稿拒绝、提醒保持、缓存同步和真实 IPC。

## 回退

整体安装此前版本可回退界面与内部协议，不回退已保存的任务计划；需要撤销数据变化时使用用户事先导出的 v5 备份。本次没有结构迁移。
