# 决策提案：正式版更新与安全安装

状态：源码已实现，用户授权的本地手动覆盖安装及启动已验证；隔离 Windows 安装、卸载和真实更新安装链路待验收。

## 问题

应用缺少版本和更新入口。更新器默认的自动下载、退出安装不符合用户主动确认的要求；当前关闭行为可能转入托盘，安装退出需要协调所有窗口及数据库资源。

## 方案

采用固定版本的 electron-updater，主进程独占更新服务，GitHub 仓库与 latest 渠道由构建配置固定。关闭预览版、降级、自动下载和退出自动安装。自动检查默认开启，启动延迟十秒执行一次，可关闭；手动检查始终可用。检查网络请求使用更新器自带超时，不新增轮询或无限重试。

版本来自运行安装包；直接启动主进程源码时读取项目清单，避免显示 Electron 的版本号。渲染进程只通过受限命令访问状态，不传入更新地址、路径或命令。

安装必须先通过所有窗口的草稿确认，保持写入锁至退出；错误释放锁并恢复编辑。托盘、提醒和数据库走同一退出清理路径。普通退出的草稿确认行为不变。

问题反馈固定打开本仓库 GitHub Issues，复制内容仅为应用版本、平台和架构；邮箱暂不展示。

## 替代方案

- 自写下载与安装管理器：增加校验、缓存、NSIS 等重复维护责任。
- 下载后退出自动安装：与用户选择安装时机冲突。
- 自动降级到 Latest：当前 RC 可能被替换成更旧的正式版。

## 风险与边界

当前安装包未签名，SHA 校验不等于发布者代码签名，不承诺消除 SmartScreen。首次启用更新功能仍需手动安装新版。旧正式 Release 未上传更新元数据时检查可能失败，不伪装为“已是最新版”，不修改旧发布资产。

新的正式发布须同次生成 EXE、blockmap、SHA-256 与 latest.yml，并执行 `pnpm check:release <输出目录>`。该检查验证元数据、大小、EXE 哈希及资产存在，不代替 NSIS 安装和 blockmap 内容验收。

## 验证与回退

服务状态机、正式版本比较、取消及失败分支通过自动化验证；包内 EXE 测试不证明安装流程。验收记录见 `docs/EVIDENCE-updates-batch.md`。可关闭自动检查；回退须完整退出后整体安装旧版，需要恢复数据时使用用户导出的备份，不在应用内自动降级。
