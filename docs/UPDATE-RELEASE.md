# 正式更新发布与验收

## 构建与资产

只有经过单独批准的正式版本才能发布。先更新 package.json 的正式版本和锁文件，再在干净候选上完成类型检查、单元、浏览器与桌面验证。安装包应有唯一输出目录，使用 `pnpm package --win nsis --x64 --publish never -c.directories.output=<目录>`，PowerShell 中将整个 `-c...` 参数加引号。

安装包通过后生成同名 `.exe.sha256`，内容为小写 SHA-256、两个空格及 EXE 文件名，UTF-8 无 BOM。运行 `pnpm check:release <目录>`；必须提供同次构建的 EXE、EXE.blockmap、EXE.sha256、latest.yml。检查器从包清单读取版本，拒绝 RC、跨版本文件、哈希不符或缺失资产。

按原发布流程先上传 Draft，回下载四项资产对比 SHA-256，再在独立授权下设为正式 Release 和 Latest。不得将这一步与构建自动绑定，不替换已有发布资产。

## 隔离 Windows 验收

使用可丢弃 Windows 虚拟机或专用测试系统，不在开发者日常环境试装、覆盖或卸载。当前没有可用隔离环境时保持待验收。

1. 首次安装：检查路径选择、启动、版本、SQLite 模块、托盘与退出。
2. 覆盖旧版：构造任务、完成记录、复盘、快速捕获和详情草稿、标签及设置，完全退出后覆盖，重启逐项核对。
3. 更新安装：准备两个递增的正式格式测试版本和仅测试构建使用的本地更新源；运行真实下载、校验、确认安装及重启。生产构建不得保留可由渲染进程指定更新源的接口。
4. 失败流程：断网、断下载、错误 SHA-512、重复点击、取消下载、多窗口草稿失败、安装器启动失败；验证不意外安装、不丢输入，可继续编辑或重试。
5. 普通退出：已下载后直接退出不得安装；再次打开由用户检查、确认后继续。卸载及重新安装是否保留测试数据分别记录，不以包内 EXE 启动代替安装验收。

本次不含账号服务、遥测、签名证书采购或公开发布。未签名提示与真实安装风险必须保留在后续发布说明中。
