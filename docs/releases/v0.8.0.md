# Rumo-Flow v0.8.0

正式版，发布目标为 GitHub Latest。包含 v0.7.0-rc.1 的草稿能力，以及任务计划、心流行动、设置与桌面外观改进。

## 主要变化

- 执行计划与截止日期独立，支持日、周、月计划和今日重点；总计划、本周、本月、逾期视图帮助逐步安排任务，未完成计划不会自动滚动到今天。
- 批量完成、移动清单、添加标签、修改计划和截止日期；回收站按删除批次恢复，超过 30 天的清理保护较新删除的后代。
- 心流默认三问，可展开六问并共用草稿；已保存复盘或视频可创建多个关联行动，支持任务与来源双向跳转，以及正式任务、视频和复盘搜索。
- 标签管理移至独立业务页面，视频额度和复盘提醒回归心流；设置只保留外观、快捷键、数据与备份。
- 修复偏好保存和换肤，统一设置布局、滚动条及 Windows 标题栏主题；任务、心流和快捷捕获继续支持独立草稿。
- 按职责收敛偏好和导航依赖，拆分计划、批量命令、回收站与行动服务，不引入旧实现适配层。

## 升级与回退：请先阅读

1. 升级前用旧版导出备份并正常退出，保留旧版备份供旧版恢复。不要复制正在运行中的 SQLite 数据库。
2. 本版仅导入和导出 `rumo-flow-backup` v5，包含计划、回收站、行动来源及草稿。**v1–v4 JSON 备份明确拒绝导入**，不会因此清空当前数据；这不等于拒绝已有数据库的应用内升级。
3. 数据库迁移 9 在变更前通过 `VACUUM INTO` 写入一致性快照 `backups/pre-planning-*.sqlite`。旧任务保留编号和截止日期，初始计划为未安排；任务草稿升级到 v2。
4. 降级必须先关闭全部应用进程，再恢复升级前 SQLite 快照。不要让旧程序打开升级后的数据库，也不要用旧程序导入 v5；升级后的新增数据不会包含在升级前快照中。
5. 导入 v5 会替换当前正式数据及草稿，导入前自动保存当前 v5 快照。只有界面显示“草稿已保留”才代表落盘，强制结束或断电可能丢失最后输入。

## 发布门禁

功能实现阶段的结果见 `docs/EVIDENCE-planning.md` 和 `docs/EVIDENCE-preferences.md`；这些历史记录不替代本版安装包验证。

正式发布前要求在最终提交上通过类型检查、单元与 SQLite 测试、浏览器模拟接口测试、生产构建、真实 Electron 测试；随后构建全新的 Windows x64 NSIS 包，并通过打包 EXE 的同一组桌面测试。所有桌面测试使用隔离临时用户目录，不接触个人数据库。

包检查包括版本、`app.asar` 与构建输出逐文件一致性、原生 SQLite、blockmap 结构和分块边界、签名状态、SHA-256。先上传 Draft Release，回下载并比较三项资产的哈希，再正式发布；实际执行结果和安装包哈希记录在 GitHub Release 正文中。

## 已知边界

- 正式发布不表示所有桌面场景已经验收。实际 NSIS 安装、覆盖升级、卸载、个人数据迁移与现场回退没有执行；不以解包 EXE 测试替代这些验收。
- 系统通知点击、托盘和全局快捷键的人工操作、断电恢复及长时间运行仍待验收。数据库迁移与回退相关检查仅针对临时测试数据库。
- 安装包未签名，Windows SmartScreen 可能显示提示。请只从项目 Release 下载，并使用 `Get-FileHash -Algorithm SHA256` 核对安装包。
- 发布资产仅包含 `.exe`、配套 `.exe.blockmap` 和 `.exe.sha256`，不包含个人数据、测试目录或解包程序目录。
