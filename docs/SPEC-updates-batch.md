# 更新与批量操作规格

状态：源码及本地自动化已完成，隔离 Windows 安装升级待验收。依据本轮用户已批准的《更新与反馈、批量操作优化方案》，基线 `3d66f3b`。

## 行为

- 设置提供运行版本、正式版检查、默认开启的启动检查开关、手动下载和确认安装；GitHub 反馈入口不上传用户数据，邮箱为空时隐藏。
- 使用 electron-updater 6.8.9 与当前 GitHub 仓库的 latest 正式渠道；无自动下载、普通退出安装或降级。
- 更新安装须等待所有窗口保留草稿并持续禁止新写入，保存失败恢复窗口而不退出。下载取消、失败、重复请求必须收敛到可恢复状态。
- 批量选择在当前任务行和周卡片进行，底栏操作；只选当前筛选、展开分区内任务，按 ID 去重，最多 500 项。切页或筛选清空，折叠移除，排序保留。
- 批量事务检查版本与数据代次。批量安排协调窗口并拒绝目标草稿；只修改计划、重点、修改时间，保持其他字段。同步缓存使用同一多任务协议。
- 原有回收站操作语义不变，随批量请求契约调整调用方；删除旧重复选择区，不留适配层。

## 失败模型与验证

高风险边界：安装前最后输入丢失、下载重复或取消竞态、旧版本安装、旧编辑缓存回写、批量部分成功、计划操作重发提醒、刷新失败重复提交。

使用现有 Vitest、SQLite 临时数据库、localhost Playwright 和临时 userData Electron 测试；安装升级须隔离 Windows 验收，没有环境则明确未验收。不接触个人数据库，不提交、推送或发布。

新增运行依赖 electron-updater；保留包版本，增加明确 GitHub publish 配置与发布资产检查。测试夹具与文档属于本次范围；不增加分支、远程服务或持久环境配置。
